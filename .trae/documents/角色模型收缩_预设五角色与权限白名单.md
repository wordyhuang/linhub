# 角色模型收缩：仅预设 5 角色、去除角色类型、权限项 roles 白名单化

> 创建时间：2026-11-10
> 状态：待用户批准

## Context

当前 LinHub 的角色管理允许后台自建角色（按 `WORKER/FUNCTIONAL_ADMIN/SYSTEM_ADMIN` 类型创建），契约服务 `auth` 还向功能包开放 `ensureRole` 写接口。用户决定收缩：

1. 角色管理**只允许 5 个系统预设角色**：工作者、审核员（新增）、功能管理员、系统管理员、超级管理员；**不允许新增**角色，也不提供删改角色本身。
2. **取消「角色类型」维度**：角色记录不再有 `type` 字段，预设角色身份即角色本身。
3. 权限项（permissions.php 的 `roles` 字段）的所属角色**只能落在 5 个预设角色上，或为空（不限角色）**，并写入指导文档。

已确认的两个口径（AskUserQuestion）：
- 存量自定义角色：**物理清除**（连同用户绑定引用）。
- 权限项 roles 取值：**英文键常量**（`WORKER/REVIEWER/FUNCTIONAL_ADMIN/SYSTEM_ADMIN/SUPER_ADMIN`），与插槽 roles、优先级表一致。

## 实施步骤

### 1. RbacRoles 重构（核心）
文件：`code/host/linhub/host/src/rbac/RbacRoles.php`
- 常量改为 5 个预设角色：新增 `REVIEWER = 'REVIEWER'`（审核员）；保留 4 个旧常量。
- 新增 `PRESET_ROLES` 映射（固定 id → 中文名）：`role_worker`→工作者、`role_reviewer`→审核员、`role_functional_admin`→功能管理员、`role_system_admin`→系统管理员、`role_super_admin`→超级管理员。
- `ensureDefaultRoles()` 重写：upsert 5 个预设角色（无 `type` 字段，全部 `readonly=true`）；**物理清除非预设角色**并同步清理 `RbacStorage::USER_ROLES` 中的悬空引用。
- 删除 `create()/update()/delete()`（角色不可增删改）；保留 `get()/all()`。
- 移除 `TYPE_NAMES` 或改为 `PRESET_ROLES` 别名（同步所有引用点）。

### 2. HostBootstrap 角色链路调整
文件：`code/host/linhub/host/src/support/HostBootstrap.php`
- `ROLE_PRIORITY` 加 `REVIEWER => 4`，WORKER 降为 5（超管>系统管理员>功能管理员>审核员>工作者）。
- `ROLE_HOME_PATHS` 加 `REVIEWER => '/admin/home/worker'`（复用工作者首页，不新建页面）。
- `roleTypesFor()`：内部改为由用户角色 id 映射英文键常量（不再读 `type` 字段）；方法名与返回语义（英文键列表）保持不变，调用方（Home/插槽/LoginState/RbacQuery）零改动。
