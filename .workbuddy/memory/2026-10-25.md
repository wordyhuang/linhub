## lin-crm 安装后菜单点击 404 — 已修复

**根因（三个叠加问题）：**
1. **路由前缀写法错误（404 主因）**：宿主是 think-multi-app 架构，菜单 URL 由 `url($route)` 生成恒为裸路径（`/crm/customer/index`，不带 `admin/`）；请求 `/crm/...` 时多应用不剥前缀（crm 不是应用名），完整路径去匹配全局路由 → 只有**裸路径规则**能命中。lin-crm 的 route.php 按 04 指引"常规模式"自写 `admin/crm/...` 前缀 → 永远匹配不上 → 404。"强制补齐=1"（Route::group('admin')）同样失效（规则变 admin/crm/... 且会弄坏 lin-trade）。
2. **迁移未执行**：17:56 安装时 S3 迁移没生效，11 张 `lg_lin-crm_*` 表缺失（500）。用 MigrationManager::installHandler 补跑成功。
3. **控制器继承可见性致命错误**：子控制器 `private function svc()` 与父类 `CrmController::protected svc(string $id)` 撞名且可见性更严 → PHP Fatal。10 个子控制器的 helper 重命名为 `service()` 修复。

**修改文件：**
- `code/plugins/lin-crm/route.php`：全部路由去掉 `admin/` 前缀（对齐 lin-trade 裸路径写法）
- `code/plugins/lin-crm/src/controller/{Analysis,Contract,Customer,Followup,Lead,Opportunity,Quotation,Report,Service,Todo}.php`：`private svc()` → `private service()`，调用点 `$this->svc()` → `$this->service()`
- `code/host/.env`：`PACKAGE_ROUTE_FORCE_ADMIN` 1 → 0（=1 会连带弄坏 lin-trade）
- `coding-guide/04_功能包开发指引.md` §7.1：追加"实测修正"注记（自写 admin/ 前缀写法在当前架构下必然 404；强制补齐模式失效待平台修正）
- `code/plugins/lin-crm/README.md` 偏离表、暂存区 `code/host/package/staging/lgg-pkg-lin-crm/`（route.php + 控制器）同步

**验证**：本地起 `php think run --port 8099`，登录后 lin-crm 全部 12 个页面路由 200，lin-trade 正常 200。

**遗留/注意：**
- 平台侧 `PackageRouteLoader` 的强制补齐机制（=1）在多应用架构下是坏的，宿主待修；短期约定：包路由一律裸路径 + FORCE_ADMIN=0。
