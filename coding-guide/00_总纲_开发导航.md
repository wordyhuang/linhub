## 二、文件夹用途与使用流程

`coding-guide/` 是**给开发 AI 看的操作手册**，与 `readme.md`（项目说明）、`memory.md`（经验沉淀）、`code-router.md`（需求→代码映射）互补：

- `readme.md` 讲"项目是什么、现状如何"；
- `memory.md` 讲"踩过的坑、验证过的做法"（\[skill]/\[eval]/\[rule]）；
- **`coding-guide/`** **讲"在这里开发时该怎么写、查哪里"**——是编码动作的约定来源。

### 推荐使用流程（每个开发任务前）

```
1. 读本文（00_总纲）：确认任务类型 → 定位到 01~08 对应指引 → 按指引中的"源码点位"跳到实际文件看第一手写法
2. 改动前先 Read 目标文件原文，不要凭记忆改（memory [eval] #1）
3. 涉及新增/修改功能包协议字段时，先读 document/ 下的协议规范
4. 编码按 TDD：先写/找验证脚本（temp/），再编码，跑通 FAIL=0
5. 改动后按对应指引的"验证门禁"回归，结论写回 memory.md
```

## 六、平台核心铁律（先看这几条）

以下几条在 memory \[rule]/\[eval] 中反复出现，违者必出问题：

1. **命名空间全小写**：平台内核是 `linhub\host\*`、`linhub\capability\*`（不是 `app\host\*`，更不是 `LinHub\Host\*`）。写 `use` 前先 grep 类文件真实 `namespace`。
2. **PHP 运行时固定** **`D:\BtSoft\php\82\php.exe`**：系统 PATH 的 `php` 是 7.2，跑 8.x 语法会全报错。
3. **平台页面/接口 URL 一律显式应用前缀**：`/admin/xxx`、`/index/xxx`，不能依赖无前缀 `url()`。**例外**：功能包 `route.php` 一律写**裸路径**（如 `trade/product/index`，不带 `admin/` 前缀），且 `code/host/.env` 的 `PACKAGE_ROUTE_FORCE_ADMIN` 保持 `0`（详见 04 第七节）。
4. **前端统一 workdesktop-ai UMD 写法**：x-template 字符串模板 + `template:'#id'`，绝不用 `app.mount('#app')` 读内联 DOM；图标用 `app.component` 注册。
5. **JSON 协议** **`{code,data,message}`**：`code>=0` 成功；`success` 只是 `WD.request` 客户端派生的字段，**原生 fetch/curl/Playwright 断言一律判** **`code`**。
6. **管理动作首行门禁**：页面用 `gate()`，JSON 用 `gateForJson()`；写操作必须 `auditTrail()->log(...)`。
7. **表前缀隔离**：功能包 `lg_<short>_`；平台统一 `lg_mgt_`（`SqlPrefixValidator::PLATFORM_PREFIXES`）。Model 用 `$table` 完整表名。
8. **TDD + 真实门禁**：交付必须能跑 `FAIL=0`，子代理报告要亲自重跑复核。
9. **密钥红线**：一律环境变量（.env），禁止写死；`.env` 进忽略规则。
10. **文档头规范**：新建文档必须带 创建/修改时间、版本、适用对象、核心目标、简略描述，末尾版本变化记录。
11. **服务优先原则（总体编码原则）**：设计功能前**先查平台服务清单**（`services/services.php` 与 08 平台服务接入指引），若已有服务能满足设计要求，**优先通过服务接入实现**，不要重复造轮子或直接读平台内核。服务不满足时，再考虑自建或新增平台服务（走 02 指引的服务注册流程）。
