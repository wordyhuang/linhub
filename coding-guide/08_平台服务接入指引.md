## 三、接入三步（声明 → 获取 → 消费）

```
① manifest 声明 services.requires
        ↓ 安装期 M006 校验（id 存在 + 版本满足）
② 运行时经 HostServiceApi 获取实例
        ↓ ServiceInjector 按清单解析、$app->make() 装配
③ 面向契约接口消费（不可实例化实现类、不可注册/覆盖宿主服务）
```

**铁律（M12）**：宿主服务对功能包**只读**——仅可消费，禁止注册、覆盖、替换宿主服务实现。

## 四、manifest 声明写法

### 4.1 services.requires — 声明依赖

```php
// manifest.php
return [
    // ...其他字段
    'services' => [
        'requires' => [
            'logging',                    // 写法一：裸 id，不约束版本
            'dictionary',
            ['llmgateway' => '^1.0'],     // 写法二：id => 版本约束
        ],
    ],
];
```

- 两种写法可混用；版本约束语义化（`^1.0`、`>=1.0 <2.0` 等），由 `manifest\VersionConstraint::matches()` 判定。
- 安装/升级期由 `ServiceDependencyChecker` 硬拦截：id 不存在或版本不满足直接失败（M006）；运行时 `ServiceInjector` 兜底再校验一次。
- 仅接口服务（filestore/scheduler）声明可通过校验，但**注入时抛"暂无宿主内置实现"**，现阶段不要写进 requires。

### 4.2 services.provides — 托管自有服务（可选）

```php
'services' => [
    'provides' => [
        ['id' => 'demo.greeter', 'class' => 'Lg\Pack\Demo\Service\Greeter'],
    ],
],
```

- 本包托管的服务进入 `ServiceRegistry::packageProvides()`，其他包可经同一注入机制消费。

## 五、统一门面 HostServiceApi

功能包获取服务实例的**唯一入口**是 `linhub\host\communication\HostServiceApi`（静态门面，无需自行实例化 ServiceInjector）：

```php
use linhub\host\communication\HostServiceApi;
use think\App;

// 取单个服务（推荐带上包 id，llmgateway 会焊死 caller=pkg.<short>）
$logging = HostServiceApi::getService($app, 'logging', 'demo');

// 批量注入（与 manifest requires 同构）
$services = HostServiceApi::inject($app, [
    'logging',
    ['dictionary' => '^1.0'],
], 'demo');
$dict = $services['dictionary'];
```

- `$app`：控制器/服务内直接用 `$this->app`；独立上下文用 `app()`。
- `$pkgId`：功能包短名。对 llmgateway **必传**——拿到的实例已被 `BoundLlmGateway` 装饰器焊死 `caller=pkg.<pkgId>`，调用时无需也不应再传 caller（显式传会被覆盖）。
- 未注册 / 版本不满足 / 无内置实现：抛 `RuntimeException`。

> 控制器内建议封装一个私有方法集中取服务，避免散落多处 `HostServiceApi::getService` 调用。

## 七、接入避坑清单

1. **白名单外 id 装不上**：requires 的 id 必须在上表 16 个之内，否则 M006 安装失败。
2. **仅接口服务不能注入**：filestore/scheduler 现阶段写了 requires 会在注入时抛异常（messaging 已实现，可正常注入）。
3. **llmgateway 必传包 id**：`HostServiceApi::getService($app, 'llmgateway', '<short>')`；漏传会被焊死成 `pkg.unknown`，审计/配额归属失真。
4. **不要实例化实现类**：永远面向契约接口；实现类的构造方式（无参友好、惰性自建）是平台内部约定，功能包 new 实现类属于越界。
5. **不要注册/覆盖宿主服务**（M12）：`provides` 的 id 建议带包前缀（如 `demo.greeter`）避免与平台 id 冲突。
6. **版本约束写在安装期**：硬性版本要求放 manifest requires 的版本约束里；运行期不要再手写版本比较逻辑。
7. **跨包调用先探测**：依赖其他功能包能力时，先经 `package` 服务 `isEnabled()` 判断，再决定是否走对方路由/事件。
8. **RBAC 查询走 auth 服务**：用户/角色/权限的只读查询统一经 `auth` 服务，不直连 rbac 内核、不读 registry JSON 文件。
9. **先读子路由再接入**：本文只讲通用接入流程；各服务的契约方法、参数语义与异常行为见 `services/<id>.md` 子路由，接入前必读。
