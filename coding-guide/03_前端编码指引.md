## 二、前端总体形态

- **前后端不分离**：ThinkPHP View 模板（`linhub/admin/src/view/<模块>/index.html`）由控制器 `fetch()` 渲染空壳，数据由前端组件异步拉 JSON 接口。
- **组件库**：workdesktop-ai（自研 Vue3 + ElementPlus），通过 UMD `<script>` 直引，挂载到 `window.WorkDesktop`（别名 `WD`）。
- **一个功能 = 一个 view 文件**：不同功能拆分到不同 `<模块>/<功能>/index.html`，**不要**把所有功能堆进同一个 HTML 的多个抽屉/弹窗里。列表页作为"容器页"，需要明细/编辑/新增等子功能时，用 iframe 组合加载对应功能的独立 view 文件（见第三"功能拆分与 iframe 组合加载"）。

## 三、页面骨架（UMD 引入 + x-template）

统一模板结构（照抄 `view/role/index.html`）：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>角色管理 - LinHub 林枢</title>
  <link rel="stylesheet" href="/static/vendor/element-plus/index.css">
  <link rel="stylesheet" href="/static/vendor/workdesktop-ai/style.css">
</head>
<body>
  <div id="app"></div>

  <!-- 模板：字符串模板，避免 in-DOM 解析缺陷 -->
  <script type="text/x-template" id="xxx-tpl">
    <div class="xxx-page">
      <wd-tips type="box" style="display:flex;margin-bottom:12px">
        本页用于维护角色与数据权限：角色是权限的集合，删除前需确认无用户使用；数据范围留空表示继承上级。
      </wd-tips>

      <wd-panel :border="true" title="角色管理" description="数据范围留空的项表示沿用上级角色默认值。">
        <wd-data-grid ref="grid" api="/admin/xxx/rows" api-method="get" :active="true" filter="xxx">
          <el-table-column label="名称" min-width="180">
            <template #default="{ row }">{{ row.name }}</template>
          </el-table-column>
          ...
        </wd-data-grid>
      </wd-panel>
    </div>
  </script>

  <!-- 加载顺序固定 -->
  <script src="/static/vendor/vue/vue.global.prod.js"></script>
  <script src="/static/vendor/element-plus/index.full.min.js"></script>
  <script src="/static/vendor/icons/index.iife.min.js"></script>
  <script src="/static/vendor/workdesktop-ai/index.umd.js"></script>

  <script>
    const WD = window.WorkDesktop;
    const { WorkDesktop } = WD;
    const { ref, reactive, watch } = Vue;

    const app = Vue.createApp({
      template: '#xxx-tpl',
      setup() {
        // ... 状态与逻辑
        return { /* 所有用到的 ref/reactive 必须 return */ };
      }
    });

    // Vue3 图标注册（必须）
    for (const [name, comp] of Object.entries(window.ElementPlusIconsVue)) {
      app.component(name, comp);
    }
    app.use(ElementPlus);
    app.use(WorkDesktop);
    app.mount('#app');
  </script>
</body>
</html>
```

> **铁律**：
>
> - **页面第一个元素必须是功能 tips（强制）**：`<wd-tips type="box" style="display:flex;margin-bottom:12px">` 放在页面根 div 顶部（panel 之前），向用户解释**当前页面的功能介绍**——页面能做什么、影响范围、关键规则/限制；`wd-panel` 上有需要注意的事项时写进 **`description`** 属性（没有就不写，不强凑）。细则见下方「页面 tips 与 panel description」。
> - **绝不用** **`app.mount('#app')`** **读取内联 DOM 当模板**——in-DOM 模板解析会在 `el-form` 之后静默截断，生产版 Vue 无任何报错（memory \[eval] #11）。统一 `<script type="text/x-template">` + `template:'#id'`。
> - 加载顺序固定：`vue → element-plus → icons → workdesktop-ai`。
> - 图标必须 `app.component(name, comp)` 遍历注册（Vue3 API；Vue2 的 `Vue.component()` 在 Vue3 抛错）。
> - `setup()` return 里漏 ref 会导致模板该数据 undefined（memory \[eval] #17）。

## 三、功能拆分与 iframe 组合加载

**背景**：早期样例把列表 + 若干新增/编辑/明细弹窗全写进同一个 `index.html`，页面臃肿、难维护、一次 SSR 全量下发。规范要求**按功能拆分 view 文件**，容器页用 iframe 组合子功能（workdesktop-ai 组件原生支持）。

### 目录约定

```
view/<模块>/
  index.html              # 容器页（列表/入口），通常一个
  <功能>/index.html       # 每个子功能一个独立 view 文件，如 create/、edit/、detail/
```

### 三种 iframe 集成方式

1. **`wd-drawer-button :url="'…'"`（最常用）**：抽屉内以 iframe 加载子功能 view。设了 `url` 后，组件不再渲默认插槽内容，而是加载该地址的独立页面。
2. **`wd-iframe`（内嵌区）**：页面内直接嵌一个 iframe 区域（`src`），用于非弹层的模块加载（如看板区）。
3. **`useIframeContainer`（子页与父容器通信）**：若子页需要拿到父容器传入数据、通知提交成功/脏状态，用组件库提供的容器 API。

### 基本用法（wd-drawer-button url 模式）

```html
<wd-drawer-button
  label="新增"
  mode="drawer"
  title="新建商品"
  :drawer-size="720"
  url="/admin/product/create"      <!-- 子功能独立 view 的访问地址 -->
  :data="{ parentId: row?.id }"    <!-- 可选：透传给子页初始化数据 -->
  @open="onOpen(row)">
  <template #footer="f">
    <!-- url 模式下子页自身关闭自身，通常无需 footer；如需父容器兜底关闭可用 f.close -->
  </template>
</wd-drawer-button>
```

- `url` 指向的是子功能 view 的**独立访问 URL**（经路由/控制器渲染出的完整页面），不是 `.html` 静态文件直观路径。
- `reloadOnOpen`：每次打开都重建 iframe（默认建议打开），避免残留旧态。
- `drawer-size`：抽屉宽度，数字按 px。
- `data`：传给 iframe 子页的初始化数据（仅同源可透传）。

### 子页 `useIframeContainer` 握手

子功能 view 内用 `WD.useIframeContainer`（若以全局别名挂在 `WD` 上）拿到容器 API：

```js
const wd = window.WorkDesktop;
const ctl = wd.useIframeContainer && wd.useIframeContainer();
ctl.connect({
  onInit(data) { /* 收到父容器 data prop，填表单 */ },
});
// 提交成功：通知父容器关闭抽屉并刷新表格
ctl.notifySubmitSuccess();
```

> **验证提示**：`useIframeContainer` 的全局暴露方式（是否挂在 `WD.*`）以 workdesktop-ai 实际 UMD 导出为准。子页若拿不到该 API，退而用 `window.postMessage` 与父容器约定消息通信（frame 内脚本 + `contentWindow`/`message` 事件）。**不要假设请求封装自动跨 iframe**——同源 iframe 内 `WD.request` 可直用；跨域需自管消息与来源校验。

## 四、常用 wd-\* 组件清单与用法

组件名以 workdesktop-ai 的 `llms.txt` / `dist/types/src/components/index.d.ts` 导出表为准，**不要凭 ElementPlus 想当然拼名字**（memory \[eval] #22）。

| 组件                     | 用途           | 关键用法                                                                                                                                                                                                                                                            |
| ---------------------- | ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `wd-station`           | 工作台整页外壳      | 登录后工作台 dashboard.html，注入 `wdState`（user/menuGroups/slots/site/msg）                                                                                                                                                                                              |
| `wd-panel`             | 内容卡片容器       | **必须有 title**，否则 header 不渲染、`#extra` 里的按钮消失（memory \[eval] #16）；面板有**需要注意的事项**（口径解释、生效规则、易误解点）时写在 `description` 属性，随 title 展示；没有注意事项则省略 |
| `wd-data-grid`         | 数据表格（列表页主力）  | `api` / `api-method` / `filter` / `:active="true"`；列用 el-table-column；`#empty` 空态；`grid.value.search({keyword})` 触发搜索                                                                                                                                           |
| `wd-drawer-button`     | 按钮弹右侧抽屉      | `label`（按钮字）、`size`（**抽屉宽度**如 "560px"）、`button-size`（按钮尺寸）、`title`、`#default` 内容、`#footer="f"`（f.close）；`@open="fn(row)"`；**`#footer`** **必须是平级子节点不能嵌进** **`#default`**。**iframe 子功能**用 `url` + `:drawer-size` + `reload-on-open`（见第三节），设 `url` 后不渲 `#default`。 |
| `wd-iframe`            | 内嵌 iframe 区域 | `src` / `height` / `:auto-height`；用于非弹层的模块嵌入（看板等），见第三节。                                                                                                                                                                                                         |
| `wd-api-button`        | 声明式调接口按钮     | `api` / `api-method` / `:api-param`（**对可能 null 的 row 用可选链**）/ `head-refresh-datagrid="filter"` / `@api-success="f.close"`                                                                                                                                       |
| `wd-popconfirm-button` | 删除等危险操作二次确认  | `title` / `tip` / `api` / `:api-param` / `head-refresh-datagrid`；按钮尺寸传 `size="small"`                                                                                                                                                                           |
| `wd-radio-list`        | 单选（按钮样式）     | `:data-source` / `text-prop` / `value-prop` / `button-style`；**不是** **`wd-radio-button-list`**                                                                                                                                                                  |
| `wd-tips`              | 说明条          | `type="box"`；**页面级功能介绍**放页面顶部（根 div 第一个元素、panel 之前，`style="display:flex;margin-bottom:12px"`）；面板/区块内的局部说明也可内嵌（自控 margin）                                                                                                                                                                                                                                                    |
| `wd-dialog-button`     | 居中弹窗按钮       | 旧式，新页面优先 wd-drawer-button                                                                                                                                                                                                                                       |

> 基础按钮库里**没有** **`wd-button`**，普通按钮直接用 `el-button`；两组件根为 Fragment，`.el-button` 直接成为按钮组子节点。

### 4.1 表格行操作列规范（强制，源自 workdesktop-ai 官方 AI 文档）

workdesktop-ai 随 npm 包发布官方 AI 编码文档（`ai-router.md` 场景路由 + `ai-api/` 分组件精确 API，可从 unpkg 拉取：`https://unpkg.com/workdesktop-ai@<版本>/ai-router.md`，包内也有副本）。写操作列前**必读** §1.7 行操作列规范与 §0.13 按钮选型，要点如下（lin-crm 功能包为参考实现）：

1. **按钮选型按「点击后要发生什么」**：直接动作 → `wd-api-button`（自动 loading/成功失败提示/联动刷新）；行内抹除操作（删除/停用/退回）→ `wd-popconfirm-button`（气泡轻确认，不打断上下文）；工具栏/批量/不可恢复操作 → `wd-confirm-button`（MessageBox 强打断）；单字段输入后请求（回收原因/驳回意见）→ `wd-prompt-button`（输入值经 `param-key` 并入 `api-param`，失败保留弹窗可改）；新增/编辑（4-15 字段）→ `wd-drawer-button`，≤3 字段轻量录入用 `mode="dialog"`；详情查看也用 `wd-drawer-button`（§0.7：新内容优先抽屉，不做页面跳转）。
2. **确认分级**（§0.9）：单个删除/启停 = L1 确认（文案公式：操作 + 对象 + 后果 + 不可逆提示）；批量删除/清空/不可恢复 = L2 强确认；进回收站可恢复的删除按 L1。
3. **状态不可用口径**（§1.7）：状态流转不可逆导致的永久不可用 → `v-if` 不渲染（不渲染灰色禁用按钮挤占空间）；仅临时不可用（必填未填、处理中）→ `disabled` + tips 说明原因。
4. **布局**：操作列 `fixed="right"`、按钮 `el-button-group` 包裹统一 `size="small"`；1-2 个最高频操作外露，低频收纳「更多」`el-dropdown`（下拉项内用 ElMessageBox 确认，不能嵌 popconfirm/tips）；行内抹除操作外露时优先 `wd-popconfirm-button`。
5. **弹层闭环**：`#footer="f"` 内「取消（`f.close`）+ `wd-api-button`（`head-refresh-datagrid="<filter>"` + `@api-success="f.close"`）」——成功提示与表格刷新由组件自动完成，不要手写 ElMessage/refresh；必填校验用 `:disabled` 拦截提交按钮。弹层内容懒挂载（首次打开才渲染），表单状态由 `@open="fn(row)"` 预填。
6. **head-refresh-datagrid**：值 = 目标 grid 的 `filter` 名（字符串 = 定向刷新，`true` = 同 filter 组）；操作不改表格数据时显式 `:head-refresh-datagrid="false"` 关掉，纯 el-table 页面（无 wd-data-grid）用 `@api-success="load"` 手动重载。

## 五、WD.request 数据请求

```js
const WD = window.WorkDesktop;

// GET：第二参是裸参数对象不是 axios config；带参请求统一用 qs() 拼 query
function qs(obj) {
  const p = new URLSearchParams();
  for (const [k, v] of Object.entries(obj)) { if (v !== '' && v != null) p.append(k, v); }
  const s = p.toString();
  return s ? '?' + s : '';
}

WD.request.get('/admin/xxx/rows' + qs({ keyword })).then(res => {
  if (!res.success || !res.data) return;      // 必须兜底
  items.value = res.data.list || [];
});

WD.request.post('/admin/xxx/save', { id, name }).then(res => {
  if (!res.success) return;
  WD.refreshDataGrid('xxx');                   // 刷新指定 filter 的 data-grid
});
```

- **`WD.request.get(url, params)`** **的第二参是裸参数对象**，不是 axios 的 `{params:{...}}`——传 `{params}` 不会拼进 URL（memory \[eval] #40）。带参 GET 统一用 `qs()` helper 手动拼。
- 成功后刷新表格：`WD.refreshDataGrid(filter)`，或在 wd-api-button 上用 `head-refresh-datagrid="filter"` 自动刷新。
- 多行数据取 `res.data.list`，先判 `!res.success || !res.data`。

## 六、JSON 协议与响应判断

- 后端统一信封：`{code, data, message}`，`code >= 0` 成功（见 02 指引 §五）。
- **`success`** **只存在于** **`WD.request`** **包装层**（解包派生 `{success, data, code, message, raw}`）；`code>0` 的失败也可能 `success=true`。
- **原生 fetch / curl / Playwright APIRequestContext 断言一律判** **`code`**，不要判 `success`（memory \[eval] #24/#37）。

```js
// 页面内（有 WD.request 包装）：用 res.success
WD.request.post('/admin/xxx/save', p).then(res => { if (res.success) { ... } });

// 页面外/断言：判 code
const r = await fetch('/admin/xxx/rows');
const j = await r.json();            // {code, data, message}
if (j.code === 0) { ... }
```

## 七、页面与后端 JSON 接口的对应关系

管理页惯用接口命名（与控制器 action 对应）：

| 用途    | 后端 action                             | 前端用法                                                                       |
| ----- | ------------------------------------- | -------------------------------------------------------------------------- |
| 列表    | `rows`（GET）                           | `wd-data-grid api="/admin/xxx/rows"` 或 `WD.request.get('/admin/xxx/rows')` |
| 下拉选项  | `options`（GET）                        | 打开抽屉时拉取                                                                    |
| 保存/新增 | `save`（POST）                          | `wd-api-button` 或 `WD.request.post`                                        |
| 删除    | `delete`（POST）                        | `wd-popconfirm-button`                                                     |
| 其他子动作 | `members`/`perms`/`assign`/`choose` 等 | `WD.request.get/post`                                                      |

- 返回结构：列表 `{list, total}`；明细/详情 `{...字段}`。
- 写操作成功后后端会返回 `code=0` + message；前端可弹 ElMessage 或直接刷新。
- 需要条件渲染（如"未安装才显示安装按钮"）用 `v-if`，不要把按钮的渲染前提写死进断言。

## 八、前端避坑清单

1. **模板**：x-template 字符串模板 + `template:'#id'`，禁 in-DOM。
2. **图标**：`app.component` 遍历注册（Vue3）。
3. **组件名**：以组件库导出表为准；渲染空白且 console 干净 → 先怀疑组件名未注册。
4. **`:api-param`**：对可能为 null 的嵌套对象用可选链 `dlg.row && dlg.row.id`。
5. **`WD.request.get`** **带参**：用 `qs()` 拼 URL，不用 `{params}`。
6. **`res.data`** **兜底**：取 `res.data.list` 前判 `!res.success || !res.data`。
7. **`setup`** **return**：所有模板用到的 ref 都要 return。
8. **`wd-panel`**：必须设 title。
9. **静态 JS 改版**：给 `<script src>` 加版本参数（如 `home-link.js?v=2`）绕浏览器缓存（memory \[eval] #21）。
10. **断言**：E2E / 原生请求判 `code`，不判 `success`；Playwright 定位 drawer 用 `.el-overlay.is-drawer .el-drawer.open` 最后一个，popconfirm 用 `.el-popper:visible`。
11. **不要把一个模块的所有功能堆进单个** **`index.html`**：按功能拆分 view 文件，用 `wd-drawer-button url`/`wd-iframe` 组合加载；DRY 不通过"一个大 HTML 塞 N 个抽屉"实现。
12. **iframe 子页拿不到** **`WD.useIframeContainer`**：全局暴露以 workdesktop-ai UMD 导出为准；拿不到就退回约定 `postMessage`（含来源校验）。子页表单默认自管关闭，提交成功记得 `notifySubmitSuccess()` 让父容器关抽屉 + 刷表格。
13. **同源 iframe 内** **`WD.request`** **可直用**，勿在子页重刻请求封装；跨域才需自管 message 与 targetOrigin。

- **V1.2（2026-10-27）**：页面骨架新增「页面功能 tips（强制）」——每个页面根 div 第一个元素必须是 `<wd-tips type="box" style="display:flex;margin-bottom:12px">`，向用户解释当前页面的功能介绍（能做什么、影响范围、关键规则/限制），放 panel 之前；`wd-panel` 有需要注意的事项时写进 `description` 属性（没有则省略不强凑）。第三节骨架模板同步更新示例，铁律加第 1 条，第四节组件表扩充 `wd-tips`（页面级/局部两种用法）与 `wd-panel`（description）行；参照 `code/plugins/lin-crm/src/view/setting/config.html` 双用例。
- **V1.1（2026-10-21）**：新增第三节「功能拆分与 iframe 组合加载」——确立"一个功能 = 一个 view 文件"的目录约定，容器页用 `wd-drawer-button url` / `wd-iframe` 组合子功能，子页经 `useIframeContainer` 握手（connect / notifySubmitSuccess）。同步更新总体形态、wd-\* 组件清单（补 `url`/`wd-iframe` 用法）与避坑清单。
- **V1.0（2026-10-12）**：初版。覆盖 UMD 骨架、x-template 范式、wd-\* 组件、WD.request 协议、JSON 判断与前端避坑。
