## 二、单库架构（先读结论）

**LinHub 当前是单库架构：平台表与功能包表全部落在同一个系统库 `lin_hub`，没有独立的"用户库/业务库"。**

- `.env` 只有一套 `DB_*` 配置（`DB_NAME = lin_hub`），ThinkPHP 全部连接指向这一个库。
- 平台公共服务表（`lg_mgt_*`）、平台管理表（`lg_mgt_*`）、功能包表（`lg_<short>_`）**同库**——功能包迁移经 `MigrationManager` 用的也是同一 PDO 连接（HostBootstrap 按 config/database.php 装配）。
- 隔离靠**表前缀**，不靠分库：`SqlPrefixValidator` 安装期校验功能包只能建 `lg_<short>_` 前缀表，平台前缀（`lg_mgt_`）保留不可占用。

**含义与取舍**：

| 面 | 说明 |
| --- | --- |
| 优点 | 一套连接部署简单；schema 差异看板、跨包治理天然同库可行 |
| 代价 | 功能包与平台数据物理混库，无库级权限/备份粒度隔离；库随功能包增多膨胀 |
| 未来分库改造点 | `MigrationManager::fromPdo()` 连接注入处换一套 PDO；前缀校验与迁移账本无需动 |

> 写代码时记住：没有任何"切库"操作可用，所有 SQL 都跑在 `lin_hub` 上——跨包读别人表前缀的数据属违规行为，跨包数据交互走事件或服务 API。

## 三、表前缀隔离规则

| 归属 | 前缀 | 说明 |
| --- | --- | --- |
| 功能包 | `lg_<short>_` | 如 `lg_demo_record`；同一功能包全部表用同一前缀 |
| 平台管理 / 公共服务 | `lg_mgt_` | 迁移记录、服务/能力/画像、消息、附件、字典、LLM、RBAC 等平台表统一 `lg_mgt_`（如 `lg_mgt_service`、`lg_mgt_capability`） |

- 前缀白名单（`SqlPrefixValidator::PLATFORM_PREFIXES`）：`['lg_mgt_']`——功能包表前缀 `lg_<short>_` 不能撞这个保留前缀。
- 功能包在 `manifest.resources.database` 声明表时，M005 会校验前缀与冲突（是否与已装包占用表冲突）。

## 四、迁移引擎与迁移脚本

迁移引擎位于 `code/host/linhub/host/src/migration/`（S3）：

- `DbGateway` / `PdoGateway`：数据库网关（真实 MySQL）；`exec`/`query`/`quote`，**不支持 `prepare()`**（见避坑）。
- `MigrationManager`：提供 `installHandler/upgradeHandler/rollbackHandler`，返回 `(array $manifest): void` 闭包，注入功能包安装器槽位。
- `MigrationVersion` / `MigrationTable` / `MigrationAuditLog`：迁移版本、迁移表、迁移审计。
- `SchemaSnapshot` / `SchemaDiff`：Schema 快照与差异（供 Schema 差异看板）。
- `SqlPrefixValidator`：前缀校验。
- `BackupEngine`：迁移前备份。

### 迁移脚本目录与命名

```
{loadRoot}/<short>/migrations/<版本号>/
├─ 001_<描述>.up.sql     # 向前迁移
└─ 001_<描述>.down.sql   # 回滚
```

- 目录名 = 语义化版本号（如 `1.0.0`）；文件名 `<序号>_<描述>.up.sql / .down.sql` 成对。
- `manifest.migrations` 字段声明迁移目录名（默认 `migrations`）。
- 安装/升级执行 up；回退执行 down；幂等（重复执行不产生脏数据）。

> 迁移脚本完整协议见 `document/林工_基础平台_功能包协议规范_v1.0.md`；真实示例见 `code/plugins/lin-trade/migrations/1.0.0/`（首装建表）与 `1.1.0/`（升级加表，均为已安装包，只读参考）。

## 五、Schema 快照与差异

- `SchemaSnapshot` 采集表结构快照；`SchemaDiff` 计算两快照差异。
- Admin 的 **Schema 差异看板**（`/admin/schema/diff`）比对功能包声明表与真实库结构的差异，供评审迁移。
- 改动迁移/建表逻辑后，可在看板验证差异是否符合预期。

## 六、Model 写法

功能包内 ThinkPHP ORM Model：

```php
<?php
declare(strict_types=1);

namespace Lg\Pack\Demo\model;

use think\Model;

class Record extends Model
{
    // 必须用完整表名；不要用 $name + $prefix（ThinkPHP 不读独立 prefix）
    protected $table = 'lg_demo_record';
}
```

> 平台内核/管理页读写数据库时，优先经服务层（如 `PlatformStore`）或网关，避免直接散落 SQL。

## 七、平台共享表（lg_mgt_）

- 平台公共服务（附件/字典/登录态/消息/LLM/服务画像等）统一经 `linhub\host\services\support\PlatformStore` 与 `LinserviceStore` 落库 `lg_mgt_*` 表。
- `PlatformStore` 建表走 `ensure*Tables()` 幂等。
- 功能包**不得**直接使用/占用 `lg_mgt_*` 表；需要持久化时用自己的 `lg_<short>_` 表或经公开服务 API。
- 共享表字段以现有 Service 的真实字段为准（如消息接收表用户字段是 `user_id` 不是 `recipient_id`，memory [eval] #30），**不要凭语义改名**。

---

## 八、数据库操作避坑

1. **网关无 `prepare()/quote()`**：`PdoGateway` 只有 `exec/query`；参数转义走 store 的 `quote()`，SQL 全字符串拼接 + exec/query（memory [eval] #29）。
2. **字段名以真实建表为准**：写 SQL 前 grep 既有 Service 的真实字段；JOIN 字段带表别名。
3. **幂等重置**：直连真实库的联调脚本开头 reset 自身染指状态（DROP/清理），保证可重复运行（memory [skill]）。
4. **迁移回滚**：`rollback` 槽位只收 `['version'=>x]`，须外层补 `short` 与 `migrations`。
5. **表前缀**：新表必须带正确前缀，撞保留前缀会 M005 拦截。
6. **PHP 运行时**：跑迁移/建表脚本用 `D:\BtSoft\php\82\php.exe`。
