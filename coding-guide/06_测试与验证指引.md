## 二、TDD 开发流程

按 `agents.md` 与 `memory.md` [hooks] 的要求：

```
1. 先确定验证标准（要测什么、断言什么）
2. 编码
3. 跑验证脚本 → 看 PASS/FAIL
4. 有 FAIL → 修复 → 复验，直到 FAIL=0
```

- 任何新功能/修复都要有对应的验证脚本，落在 `temp/`。
- 交付结论以**亲自重跑**的 `PASS=N FAIL=0` 为准，**不信任子代理/他人报告的数字**（memory [eval] #7）。
- 结论写回 `memory.md` 对应分类（[skill]/[eval]/[hooks]）与 `code-router.md`。

## 三、PHP 运行时与常用命令

> ⚠️ **PHP 运行时固定 `D:\BtSoft\php\82\php.exe`（8.2）**。系统 PATH 的 `php` 是 7.2，跑 8.x 语法（readonly/命名参数/枚举）会全报错（memory [eval] #4）。

```powershell

# 跑验证脚本（看 PASS=N FAIL=0）
D:\BtSoft\php\82\php.exe temp/xxx_test.php

# 类自动加载自检（改平台库/服务后）
D:\BtSoft\php\82\php.exe -r "var_dump(class_exists('linhub\\host\\support\\HostBootstrap'));"

# 启动开发服务器（真机冒烟）
D:\BtSoft\php\82\php.exe think run -H 127.0.0.1 -p 8213

# 重新生成自动加载（改 composer / 移动平台库目录后必须）
composer dump-autoload
```

> PowerShell 内联 `php -r` 双引号会吞 `$var`，用单引号或写 `temp/*.php` 脚本执行（memory [eval] #32）。

## 四、验证脚本规范（temp/）

- 命名：`temp/<模块>_<功能>_test.php`（纯逻辑单测）、`temp/<场景>_e2e.py/.js`（Playwright 真机）。
- 输出：结尾统一 `===== PASS=N FAIL=N =====`，FAIL=0 才算通过。
- 结构：
  - 引 `vendor/autoload.php` + 必要的 app 引导；
  - **隔离存储**（临时目录/内存实现），不污染生产数据；
  - **幂等重置**：会写持久状态的脚本开头先 reset 自身染指的数据（见下节）；
  - 断言明确、失败信息完整（不要编造成功）。
- 引用类前先 grep 类文件真实 `namespace`（全小写 `linhub\host\*`）。

## 六、真实环境联调范式（MySQL/Redis/UAIS）

直连真实外部服务的联调脚本（`temp/t3_mysql_live_test.php`、`temp/t6_redis_live_test.php`、`temp/uais_live_test.php`）：

1. **脚本开头重置自身染指的全部状态**（DROP 表、DELETE 迁移/审计记录、清 key），保证任意次运行结果一致，不依赖"空态"假设（memory [skill]）。
2. **抽象/内存实现隔离逻辑层**：DbGateway/RedisStreamClient/IdentityProvider 提供内存或 JSON 实现跑纯逻辑，真实服务留联调。
3. **联调结论写回** `memory.md` [vault] 的「真实环境验证」与 `code-router.md`。
4. 字段契约以真实响应 dump 为准，不要假设跨端口字段一致（memory [eval] #10）。

## 七、真机验证工具（curl / Playwright）

### curl（Windows 下优先用 `curl.exe`，不用 Invoke-WebRequest 的 session）

```powershell
# 登录（保存 cookie）
curl.exe -c cookies.txt -d "username=demo-admin&password=..." http://127.0.0.1:8213/admin/auth/login -L -o login.html

# 带 cookie 访问受保护 JSON 接口（断言 code）
curl.exe -b cookies.txt "http://127.0.0.1:8213/admin/role/rows?keyword="

# 未登录应 302 跳登录页
curl.exe -I http://127.0.0.1:8213/admin/role/rows
```

> 断言裸 HTTP 响应**一律判 `code`**（`success` 仅前端 WD.request 有，见 03 指引 §六）。

### Playwright

- 真机端到端脚本（Python `temp/*_e2e.py` 或 Node `temp/*_e2e.js`）：
  - 登录走真实路由 `POST /admin/auth/doLogin`（demo-admin 走 mock 超管直通）；
  - 断言渲染元素 + **console/page 错误为空**；
  - 写操作/造数据的 E2E 先幂等清理上轮残留，跑完自清理；
  - 抽屉定位 `.el-overlay.is-drawer .el-drawer.open`（最后一个）、popconfirm 定位 `.el-popper:visible`；
  - 断言 `code` 不判 `success`（memory [eval] #24/#37）。
- 常用浏览器脚本基准：`temp/api10_regression.py`、`temp/g9_2_e2e.py`、`temp/notice_e2e.js`。

## 八、验证纪律

1. 数字只信亲自重跑的：`PASS=N FAIL=0` + 文件真实落盘。
2. 环境真实暴露：无法完成 / 验证失败 / 环境缺失 / 网络失败，直接说明，不掩盖。
3. 不编造不存在的测试、构建结果、git 远端、依赖版本或浏览器验证。
4. 每阶段交付须有对应 `temp/` 脚本；改动后按门禁清单回归对应项。
