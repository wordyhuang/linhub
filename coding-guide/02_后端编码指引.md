## 二、后端代码分层与放置

| 代码类型    | 放置位置                                                       | 说明                                               |
| ------- | ---------------------------------------------------------- | ------------------------------------------------ |
| 管理页控制器  | `code/host/linhub/admin/src/controller/*.php`              | 命名空间 `app\admin\controller`，继承 `AdminController` |
| 管理页路由   | `code/host/linhub/admin/src/route/app.php`                 | 显式登记                                             |

## 三、控制器范式（页面 + JSON 接口）

### 3.0 页面还是 JSON（先判定再落笔）

一个控制器 = 页面方法（渲染 GUI）+ 数据方法（返回 JSON）。**先看请求是谁发起的**：

| 请求来源                                                  | 返回                          | 典型方法名                                  |
| ----------------------------------------------------- | --------------------------- | -------------------------------------- |
| 浏览器直访：叶子菜单 `route`、地址栏输入、`window.open` / iframe `src` | **HTML 页面**                 | `index` / `pageXxx`                    |
| 前端组件异步拉取：data-grid 数据源、保存/删除按钮、下拉选项、详情弹窗              | **JSON**（`jsonOk/jsonFail`） | `rows` / `save` / `detail` / `options` |

> 红线：**`menus.php`** **声明** **`route`** **的叶子菜单必须指向返回 HTML 的页面方法**——菜单路由指向 JSON 方法，浏览器直接输出一屏 JSON，等于页面缺失。页面路由与数据路由分离：`GET <路径>` 渲染页面，`POST <路径>/rows` 返回列表 `{list, total, pageSize, currentPage}`。

页面渲染写法按代码归属分两种，**不可混用**：

### 3.1 宿主 admin 控制器（view->fetch）

统一继承 `AdminController`，宿主已配 view\_path，页面走 `$this->app->view->fetch()`（模板写法见 03 前端指引）：

```php
<?php

declare(strict_types=1);

namespace app\admin\controller;

use linhub\capability\auth\Identity;

class Xxx extends AdminController
{
    /** 页面壳：渲染空壳，数据由前端组件拉 JSON 接口。 */
    public function index()
    {
        $gate = $this->gate();
        if (!$gate instanceof Identity) {
            return $gate;
        }
        return $this->app->view->fetch('xxx/index');
    }

    /** JSON 列表接口（data-grid 数据源）。 */
    public function rows()
    {
        $gate = $this->gateForJson();
        if (!$gate instanceof Identity) {
            return $gate;
        }
        $items = $this->buildRows();
        return $this->jsonOk(['list' => $items, 'total' => count($items)]);
    }

    /** JSON 写接口：校验 → 业务 → 审计 → jsonOk/jsonFail。 */
    public function save()
    {
        $gate = $this->gateForJson();
        if (!$gate instanceof Identity) {
            return $gate;
        }
        $identity = $gate;
        try {
            // 1. 取参 + 校验（非法直接 jsonFail）
            // 2. 业务处理
            // 3. 审计留痕
            $this->bootstrap->auditTrail()->log('xxx.save', $id, (string) $identity->name, ['xxx' => $xxx]);
            return $this->jsonOk(['id' => $id], '保存成功');
        } catch (\Throwable $e) {
            return $this->jsonFail($e->getMessage());
        }
    }
}
```

- 页面 action 与 JSON action 都**首行门禁**（见下节）。
- 私有方法（`buildRows` 等）把业务逻辑与响应拆开，便于隔离单测。

### 3.2 功能包控制器（View 渲染 + return 字符串）

包控制器继承包内基类（如 lin-crm 的 `LinCrmBaseController`）。宿主未给包配 view\_path——**页面方法用** **`think\facade\View`** **渲染并直接** **`return`** **字符串**（框架自动包装为 Html 响应），运行时先把引擎 `view_path` 指到包内 `src/view/`；**页面方法不要声明返回类型**（门禁失败时需返回 redirect/Response，与字符串混合返回，声明类型会触发 `Return value must be of type ...` 运行时错误）：

```php
use think\facade\View;

/** 页面壳：门禁 → 渲染空壳，数据由前端组件拉 JSON 接口。 */
public function pageCustomer()
{
    $gate = $this->gatePage('crm:customer:view'); // 未登录 302 登录页；无权限 403；通过返回身份
    if (!$gate instanceof Identity) {
        return $gate;
    }
    return $this->render('customer/index');       // 字符串直接返回，框架包装响应
}

protected function render(string $template, array $data = []): string
{
    $viewPath = dirname(__DIR__, 2) . '/src/view/';
    if (!is_file($viewPath . $template . '.html')) {
        abort(404, '页面缺失：' . htmlspecialchars($template));
    }
    View::engine()->config(['view_path' => $viewPath]);
    return View::fetch('/' . $template, $data);
}
```

- 视图文件 `src/view/<模块>/<页面>.html`：纯静态 HTML + 前端 JS（Vue3 + ElementPlus + workdesktop-ai UMD 直引），无服务端模板变量；页面不含 `{$var}`/`{:fn()}`/`{if}` 等模板语法时引擎渲染无副作用（lin-crm 逐字节比对验证）。
- `file_get_contents` 读文件直返亦合规（lin-trade 的 `TradeController::render()` 写法），**范式优先**；页面确需模板敏感语法时用 `{literal}...{/literal}` 包裹 JS 或退回读文件直返。
- 包基类门禁封装：页面用 `gatePage($code)`（未登录 302），JSON 用 `gateForJson()` 等价物（未登录 jsonFail）；参照源码 `code/plugins/lin-crm/src/controller/LinCrmBaseController.php`。
- 完整规范（视图骨架四件套、数据网格形状、参数兼容、多视角复用、菜单↔路由↔方法↔视图四级对齐自检）见 **04 功能包开发指引 7.2**。

## 四、身份门禁（gate / gateForJson）

| 场景       | 方法                     | 未登录                           | 已登录非超管                          |
| -------- | ---------------------- | ----------------------------- | ------------------------------- |
| 页面（HTML） | `$this->gate()`        | 302 跳 `/admin/auth/login`     | 403 页                           |
| JSON 接口  | `$this->gateForJson()` | `jsonFail('未登录或会话已失效', -401)` | `jsonFail('无权限访问平台管理接口', -403)` |

```php
$gate = $this->gate();                    // 页面
if (!$gate instanceof Identity) { return $gate; }

$gate = $this->gateForJson();             // JSON
if (!$gate instanceof Identity) { return $gate; }
$identity = $gate;                        // 后续用身份名做审计
```

> 铁律：**业务语义错误码必须在抛出点直接** **`return $this->jsonFail($msg, 码)`**，不能 `throw` 后靠外层 catch（会被兜成默认 500）。示例：功能包未审核时 `return $this->jsonFail($msg, 423)`。

## 五、JSON 响应协议

统一信封 `{code, data, message}`，由 `AdminController` 提供：

```php
$this->jsonOk($data, '成功消息');                 // code = 0
$this->jsonFail('失败原因', 500, $data);          // code = 业务码（正数）或负数
```

- **`code >= 0`** **即成功**；`success` 字段只存在于前端 `WD.request` 包装层，后端**不输出** `success`。
- 列表类数据传 `{list, total, pageSize?, currentPage?}` 结构。
- HTTP 状态码恒 200（业务码在信封内）；门禁类 JSON 接口用负业务码（-401/-403）区分。

## 六、审计留痕

所有管理写操作成功后必须写审计：

```php
$this->bootstrap->auditTrail()->log(
    'xxx.save',                    // action 码，约定 <模块>.<动作>（如 role.save / user.sync / package.review.approved）
    $targetId,                     // 目标 id
    (string) $identity->name,      // 操作人
    ['key' => 'value', ...]        // 上下文（可空数组）
);
```

- 审计码命名：小写 + 点号，`模块.动作`。
- 需要管理动作留痕时，先 grep 现成控制器中 `auditTrail()->log(` 的用法保持一致。

## 七、平台服务注册与调用

> **总体编码原则（服务优先）**：设计功能前先查下方服务清单，**已有服务能满足则优先通过服务接入实现**，不要重复造轮子或直接读平台内核（`linhub/host/src`）。服务不满足时，再考虑自建或新增平台服务（走本节"新增一个平台服务的步骤"）。
> 功能包侧通过 `manifest.services.requires` 声明 + `HostServiceApi` 接入（通用流程详见 08 总路由，各服务契约方法与接入要点见其 `services/<id>.md` 子路由）；宿主侧直接从容器取契约实现。

平台服务采用**清单化 + 垂直目录**（服务治理改造 E）：

- 服务清单：`code/host/linhub/host/src/services/services.php` —— `list` 键为服务事实来源，每项 `contract/impl/version/source/desc`。
- 目录：`services/<id>/`，接口与实现同目录（如 `logging/Logging.php` + `logging/LoggingService.php`）。
- 注册表：`ServiceRegistry` 从清单加载；`bridge/ServiceInjector` 经 `$app->make()` 注入。

**新增一个平台服务的步骤**：

1. 在 `services/<id>/` 建目录，写接口 + 实现（命名空间 `linhub\host\services\<id>`）。
2. 在 `services.php` 的 `list` 加一项，`changelog` 加 `'<id>_<version>' => [日期, 说明]`。
3. `ServiceRegistry::bootstrap()` 自动按清单注入（无需改注册表代码）。
4. 若需落库画像，经 `services/support/PlatformStore`（共享 `lg_mgt_*` 表，建表幂等）。
5. 治理页 `/admin/services/dashboard` 自动展示新服务。

**服务白名单**：`services.requires` 合法 id 当前共 17 个——`logging/config/cache/id/filestore/messaging/scheduler/attachment/dictionary/loginstate/inbox/llmgateway/package/auth/translation/recyclebin/approval`。

**服务清单速查**（以 `services.php` 为唯一权威来源）：

| 服务 id                         | 状态  | 说明                                                                                                                                                         |
| ----------------------------- | --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |

**新服务使用要点**：

- **package（PackageProbe）**：跨包协作先探测再调用——`isEnabled($name)` 为 true 才走对方路由/事件；`snapshot()` 一次拿全 installed/enabled/state/version/short；任何方法不抛异常，未装按 ABSENT 处理。
- **auth（RbacQuery）**：功能包做鉴权/菜单可见性用它而非直连 rbac 内核——`currentSnapshot()` 聚合登录态、`currentPermCodes()` 拿当前用户权限点、`userHasPermission($userId, $code)` 判他人；全部只读，底层异常吞掉返回空结构。
- **llmgateway（LlmGateway）**：经 ServiceInjector 注入的实例已被 `BoundLlmGateway` 焊死 `caller=pkg.<id>`，功能包无需也不应自填 caller；裸平台调用不传 caller 会抛 `InvalidArgumentException`；配额超限抛 `LlmQuotaExceededException`、模型不可用抛 `LlmModelUnavailableException`，调用方须 catch。
- **messaging（Messaging/MessagingService）**：事件广播/订阅走共享进程内事件总线（`communication/broker` 的 `MemoryBroker`）——主题须为 `lg.<short>.`（本方/跨包）或宿主保留前缀 `lg.platform.`；`publish` 失败不抛错（消费者失败由宿主重试后吞掉）；订阅 handler 契约为**无参构造 +** **`handle(Event $event)`**；宿主在功能包安装/卸载/升级/打包成功后经 `broadcastLifecycle()` 广播 `lg.platform.package.<installed|upgraded|removed|packed>`，功能包经 manifest `subscribes` 声明订阅、由 `PackageRouteLoader` 每请求幂等装配。

## 八、RBAC 与权限点

- 权限点编码三段或四段：`产品:资源:操作`（如 `host:services:view`、`demo:demo:view`）或 `产品:模块:资源:操作`（如 `host:llm:model:view`）——`PermissionRegistry::isValidCode()` 校验冒号数 2\~3；由 `RbacPermissionGroup` / `RbacRoles` 管理。
- 数据层：`rbac/` 下 `RbacUser`（用户-角色）、`RbacRoles`（角色类型占位）、`RbacPermissionGroup`（权限组含针对角色）、`RbacPermissionCalculator`（最终权限计算）、`AuthService`（登录/鉴权）。
- 常用入口（经 HostBootstrap）：`$this->bootstrap->roles()`、`rbacUsers()`、`permissions()`、`authService()->isSuperAdmin($identity)`。
- 超管判定：Identity tag 含 `LinHub SuperAdministrator`（UAIS）或 mock 超管身份；本地 RBAC 不自动授超管。
- 最终权限计算/可见性：`RbacPermissionCalculator` + `PermissionVisibility`（组内角色并集可见权限项）。

## 九、路由登记

新增管理端点必须在 `code/host/linhub/admin/src/route/app.php` **显式登记**，不要依赖默认路由：

```php
Route::get('xxx/index', 'xxx/index');       // 页面
Route::get('xxx/rows', 'xxx/rows');         // JSON 列表
Route::post('xxx/save', 'xxx/save');        // JSON 写
```

- 控制器名与 URL 段不匹配时显式映射（如 `services/dashboard` → `service_governance/dashboard`）。
- `home` 前缀路由须 `->completeMatch()`。
- 新增管理控制器后回跑门禁矩阵（见 06 指引）。

## 十、后端编码避坑清单

1. **命名空间**：`linhub\host\*` 全小写；写 `use` 前 grep 类文件真实 `namespace`（memory \[eval] #35/#41）。
2. **PHP 运行时**：验证用 `D:\BtSoft\php\82\php.exe`，PATH 的 php 是 7.2。
3. **`??`** **链在严格模式**：两键都不存在时仍触发 Undefined key，用 `isset()` 分支。
4. **readonly 属性不能是 callable 类型**。
5. **dirname 层级**：重构目录层级时逐一核对 `dirname(__DIR__,N)`（memory \[eval] #15/#18，Junction 加载时先 `realpath(__DIR__)`）。
6. **业务错误码直接 return jsonFail**，不要依赖 throw→catch。
7. **写操作必审计**；只读接口不写审计。
8. 控制器每个 action 首行门禁，别漏。
9. 查询参数多用 `mb_stripos` 做多字节不区分大小写过滤。
10. 返回给前端的枚举/标签用后端白名单兜底（如角色类型），不能只靠前端限制。
11. **包页面渲染**：包页面用 `think\facade\View` 渲染并直接 return 字符串（先把引擎 `view_path` 指到包内 `src/view/`），页面方法**不声明返回类型**（门禁失败要返回 redirect/Response，与字符串混返会运行时报错）；叶子菜单 `route` 必须指向返回 HTML 的页面方法，指向 JSON 方法 = 页面缺失（见第三节 3.0/3.2 与 04 指引 7.2）。
