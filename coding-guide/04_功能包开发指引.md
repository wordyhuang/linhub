## 二、平台边界（什么约束、什么自由）

- **平台约束的**：功能包对外呈现方式——目录结构、`manifest.php`、`permissions.php`、`menus.php`、`workspace.php`、`ui_replace.php`、`shortcuts.php`、`route.php`、事件订阅、表/事件/命名空间三前缀。
- **平台不约束的**：包内业务逻辑、服务类、工具类、模型、控制器、算法等原生代码（O3），可自由实例化/托管。
- **默认需登录**：不声明 `access` 即 `admin`；免登录公开端点须显式 `access=public` + `access_routes`（M010/M011）。
- **路由用标准 ThinkPHP 写法**，开发心智与 ThinkPHP 原生一致。
- **页面开发建议使用前端组件库 workdesktop-ai**：功能包若需要管理页面，建议统一用自研组件库 **workdesktop-ai**（Vue3 + ElementPlus，UMD 直引，挂载到 `window.WorkDesktop`，别名 `WD`）搭建，风格与既有管理页一致；写法、组件清单、数据请求协议与真机验证详见 [03\_前端编码指引.md](03_前端编码指引.md)。组件名以 workdesktop-ai 导出表为准，勿凭 ElementPlus 想当然拼名字（memory \[eval] #22）。

## 三、功能包目录结构

包内容结构如下；**目录名**在暂存区必须为 `lgg-pkg-<short>`，安装落地后为 `code/plugins/<short>/`（`<short>` 为全局唯一短名，小写字母/数字/`-`）：

```
lgg-pkg-<short>/
├─ manifest.php            # 包声明（核心，校验/装配的唯一事实来源）
├─ composer.json           # PSR-4 命名空间 + extra.lgg.short
├─ src/
│  ├─ Service/             # 业务服务类（可托管、可自由实例化）
│  ├─ Support/             # 工具类（原生自由）
│  ├─ Controller/          # 路由控制器（PSR-4 映射到 src/）
│  ├─ view/                # 管理页面模板（建议用 workdesktop-ai 搭建，见第二节）
│  ├─ Subscribers/         # 事件订阅处理器（无参构造 + handle(Event $event)，见第九节）
│  └─ Package.php          # 包入口类（可选，install/upgrade/rollback 钩子）
├─ migrations/<版本号>/    # 成对迁移脚本 001_xxx.up.sql / 001_xxx.down.sql
├─ route.php               # 包路由声明（可选）
├─ permissions.php         # 权限点声明
├─ menus.php               # 菜单声明
├─ workspace.php           # 工作台插槽声明（可选）
├─ ui_replace.php          # 界面替换声明（可选）
├─ shortcuts.php           # 首页快捷入口声明（可选）
└─ README.md
```

> 落地位置：**生成/暂存态**放 `code/host/package/staging/lgg-pkg-<short>/`（由 `.env` 的 `PACKAGE_STAGING_ROOT` 决定，见第十一节）；**安装后**源码落地到 `code/plugins/<short>/`（`PACKAGE_LOAD_ROOT`）；禁用后移入 `code/host/data/plugin-disabled/` 隔离区。

## 四、三个隔离前缀（必守）

| 维度   | 规则            | 示例               |
| ---- | ------------- | ---------------- |
| 命名空间 | 类只能在包命名空间内    | `Lg\Pack\Demo\*` |
| 表前缀  | `lg_<short>_` | `lg_demo_record` |
| 事件前缀 | `lg.<short>.` | `lg.demo.hello`  |

> Model 必须用 `protected $table = 'lg_demo_record'` **完整表名**（不能只写 `$name` + `$prefix`，ThinkPHP 不读独立 `$prefix`，memory \[eval] #19）。

## 五、manifest 必需字段与校验

`manifest.php` 返回关联数组。先填对以下字段，否则无法通过 M001–M011：

| 字段                   | 类型           | 必填 | 说明                                                                                                                                           |
| -------------------- | ------------ | -- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`               | string       | 是  | `组/包短名`，如 `lgg/demo`                                                                                                                         |
| `short`              | string       | 是  | 短名（小写字母/数字/`-`），与目录名一致                                                                                                                       |
| `title`              | string       | 是  | 人类可读名                                                                                                                                        |
| `version`            | string       | 是  | 语义化版本 `主.次.修订`                                                                                                                               |
| `type`               | string       | 是  | `app` / `lib`                                                                                                                                |
| `access`             | string       | 否  | `admin`（默认）/ `public`（必配 `access_routes`，M010/M011）                                                                                          |
| `access_routes`      | array        | 否  | 免登录公开路由白名单，仅 `access=public` 时生效；路径须在宿主安全探活清单内（M011）                                                                       |
| `dependencies`       | array        | 否  | 依赖图（M003 环检测）                                                                                                                                |
| `platform.host`      | string       | 否  | 宿主版本约束（M004）                                                                                                                                 |
| `resources.database` | array        | 否  | 表清单（M005 前缀/冲突校验）                                                                                                                            |
| `migrations`         | string       | 否  | 迁移目录名                                                                                                                                        |
| `services.requires`  | array        | 否  | 依赖宿主服务 id（M006，白名单见 02 指引 §七）                                                                                                                |
| `services.provides`  | array        | 否  | 本包托管服务 `[['id'=>'x','class'=>'...']]`                                                                                                        |
| `permissions`        | string/array | 否  | 权限声明文件或内联数组（M009 校验：三段或四段码）                                                                                                                 |
| `menus`              | string/array | 否  | 菜单声明文件或数组                                                                                                                                    |
| `ui_replace`         | string/array | 否  | 界面替换声明（M007 target 校验）                                                                                                                       |
| `subscribes`         | array        | 否  | 事件订阅 `[['topic'=>'lg.<short>.x','handler'=>'...']]`（M008：主题须为 `lg.<word>.` 分段——本方/跨包/宿主 `lg.platform.` 前缀均可；handler 需无参构造 + `handle(Event)`） |

> 校验错误码 M001–M011 及免登录声明细节见 `document/林工_基础平台_功能包协议规范_v1.0.md`；开发指南 V1.2 第五节有完整表格。
>
> **注意**：`workspace.php`、`shortcuts.php` 由 `IntegrationManager` **按文件名直接扫描** `loadRoot/<short>/`，**无需在 manifest 里声明**；`ui_replace.php` 既可被扫描，也可在 manifest 用 `ui_replace` / `ui_replace_file` 声明（M007 校验 target）；`permissions.php`、`menus.php` 既可写文件路径也可内联数组。

## 六、五类声明文件写法

### 6.1 permissions.php — 权限点

```php
return [
    ['code' => 'demo:demo:view',   'title' => '查看演示', 'group' => '演示管理', 'description' => '查看演示记录列表和详情'],
    ['code' => 'demo:demo:manage', 'title' => '管理演示', 'group' => '演示管理', 'description' => '新增/编辑/删除演示记录', 'roles' => ['系统管理员']],
];
```

- `code` 必须为 `产品:资源:操作` 形态，允许**三段或四段**（`PermissionRegistry::isValidCode()` 校验冒号数 2~3，如 `trade:product:view`、`host:llm:model:view`），段内小写字母/数字/下划线。
- `description`（可选）用于说明该权限项的用途，在权限管理界面展示给管理员。
- `roles` 省略/空 = 对"所有角色"可见可授权；非空 = 仅与所列角色有交集才可见。

### 6.2 menus.php — 菜单

```php
return [
    ['id' => 'demo.index', 'parent' => 'menu.workspace', 'title' => '演示记录',
     'route' => '/demo/record', 'icon' => 'Document', 'order' => 40, 'perms' => ['demo:demo:view']],
];
```

- `parent` 为字符串引用，可指向宿主预设分导台或任意已注册菜单项；多包可共用分导台。
- `icon` 取 **Element Plus 图标名（PascalCase）**，如 `User`、`Document`、`TrendCharts`——全集来自 `@element-plus/icons-vue`（本地 UMD `static/vendor/icons/index.iife.min.js`）；工作台渲染端按 `icons[icon] || icons.Menu` 键查找，**写错名不报错、静默回退成 Menu 图标**，旧式 `el-icon-` 前缀（如 `el-icon-document`）不是合法键、不会显示。可用名查 `lin-crm/menus.php` 实例或 Element Plus 官方图标页。
- 平台预设六个分导台根组（定义见宿主 `linhub/host/workspaces.php`）：

| 标识号               | 名称   | 用途                                 |
| ----------------- | ---- | ---------------------------------- |
| `menu.workspace`  | 工作区  | 普通用户日常业务操作入口（业务功能包功能默认放这里）         |
| `menu.approval`   | 审批中心 | 所有审批与待办事项的聚合入口（多包待办统一挂此处，不散落工作区） |
| `menu.system`     | 系统功能 | 系统设置、参数设置、功能配置等管理配置类入口             |
| `menu.report`     | 报表中心 | 统计报表类功能统一入口，多个功能包的报表合并挂载           |
| `menu.superadmin` | 超管功能 | 仅超级管理员可访问的平台管理功能（功能包管理、权限管理、日志审计等） |
| `menu.dev`        | 开发辅助 | 开发调试、性能分析、数据工具等辅助开发功能入口            |

#### 菜单归类指导（强制遵循）

设计功能包菜单时，先按功能性质归类，再填 `parent`：

1. **先查现有分导台与已有菜单，再定 `parent`（动手前必做）**：不要凭印象新建菜单树。先看宿主 `linhub/host/workspaces.php` 的六个分导台定义（上表），再看已装包的实际菜单——快照见 `code/host/data/integration/registry.json`，源码见 `code/plugins/<short>/menus.php`——确认目标分导台下**已有哪些一级菜单、已用过哪些 `group` 值**。然后把新菜单挂到**语义匹配的现有分导台**下；若已有同类一级菜单，优先作为其子项并入或声明相同 `group` 归组，**不另起平行的根菜单**。
2. **系统设置类 →** **`menu.system`（系统功能）**：系统设置、参数设置、功能配置等"管理员改配置"的功能。判断标准：改的是系统行为/参数，不是日常业务数据。
3. **普通用户操作 →** **`menu.workspace`（工作区）**：日常业务操作入口——录入、查询、审批、处理等"用户干活"的功能。
4. **审批 / 待办类 →** **`menu.approval`（审批中心）**：所有审批、待办、待处理事项的入口统一挂审批中心，**不散落在工作区**——各包把待办聚合页（如「审批与待办中心」）的 `parent` 填 `menu.approval`；多个包都有待办时各自挂平级叶子，由用户在同一分导台下集中处理，不自建"待办根菜单"。业务页内的审批操作按钮（如订单审核、合同通过）仍留在原业务页，只有**待办聚合入口**进审批中心。
5. **统计报表类 →** **`menu.report`（报表中心）**：所有统计、报表、看板类功能统一挂报表中心。**多个功能包都有报表时必须合并**——各包 `parent` 统一填 `menu.report`，共用同一个报表中心根组，不得各建各的报表根菜单；能合并展示的报表页面应考虑做统一入口（如一个报表聚合页），避免用户在多个零散报表菜单间跳转。
6. **超管/开发辅助类**：平台管理功能归 `menu.superadmin`（功能包一般不用），调试工具归 `menu.dev`。

#### 宿主渲染规则与 group 聚合分组

宿主左侧菜单对分导台下**一级菜单**（`parent` 直接指向分导台根组的节点）的渲染规则：

1. **默认渲染**：一级菜单挂了 `children` 后自身 `route` 被丢弃，渲染为**可折叠的子菜单**（点击展开/收起）；叶子菜单直接可点跳转。
2. **group 聚合分组**：一级菜单额外声明 `group` 字段（可选，字符串）时，前端将 **group 值相同的一级菜单聚合在同一个标题分组下**——标题行只作展示、不可点击（disabled）；组内保留各节点自身，有子菜单的仍渲染为可折叠子菜单（点击展开），叶子仍直接可点。
3. **聚合位置**：聚合组出现在该 group 值**首次出现的位置**，后续同 group 节点的子项连续追加到该组下。
4. **未声明 group**：保持默认折叠渲染，不参与聚合。
5. **跨包归组**：同一分导台下，多个功能包可声明相同的 group 值，实现多包菜单归入同一分组（如多个包的客户相关菜单都声明 `group => '客户管理'`）。

声明示例（一级折叠父节点声明 group，聚合到同一标题分组）：

```php
return [
    // 一级节点：有 children + 声明 group → 聚合到「客户管理」标题分组下
    ['id' => 'crm.customer', 'parent' => 'menu.workspace', 'title' => '客户',
     'route' => '', 'icon' => 'User', 'group' => '客户管理', 'perms' => ['crm:customer:view']],
    ['id' => 'crm.customer.list', 'parent' => 'crm.customer', 'title' => '客户列表',
     'route' => '/crm/customer', 'icon' => '', 'perms' => ['crm:customer:view']],

    // 另一个一级节点：同 group 值 → 子项追加到同一个「客户管理」标题分组下
    ['id' => 'crm.lead', 'parent' => 'menu.workspace', 'title' => '线索',
     'route' => '', 'icon' => 'Connection', 'group' => '客户管理', 'perms' => ['crm:lead:view']],
    ['id' => 'crm.lead.list', 'parent' => 'crm.lead', 'title' => '线索列表',
     'route' => '/crm/lead', 'icon' => '', 'perms' => ['crm:lead:view']],
];
```

注意事项：

- `group` 仅对一级菜单生效，深层菜单声明无效（前端只对分导台下第一层做聚合变换）。
- 父节点挂子节点后自身 `route` 会被丢弃，`perms` 填**子项权限码的并集**（菜单按权限过滤可见性）。
- group 值即分组标题文案，建议用语义清晰的中文业务名词。

- `route` 可指向包路由路径（`/demo/record`）或宿主页面；无效 route 记警告 `valid=false` 跳过，不影响其他装配。

### 6.3 workspace.php — 工作台插槽（可选）

```php
return [
    ['id' => 'demo.welcome', 'zone' => 'home.top', 'title' => '欢迎卡片',
     'render' => '/demo/ws/welcome', 'perms' => ['demo:demo:view'], 'order' => 10],
];
```

- `zone` 缺省 `home.top`，可用 `home.top` / `home.bottom`；`render` 须是单 `/` 开头的同源 URL（否则插槽被过滤）。
- 注册表归一化支持 `zone` 与 `order` 字段（见 `WorkspaceRegistry`）。

### 6.4 ui\_replace.php — 界面替换（可选）

```php
return [];
```

- `target` 必须命中平台"可替换页面清单"才合法（M007），否则装不上。

### 6.5 shortcuts.php — 首页快捷入口卡片（可选）

工作区首页（`/admin/home` 及各角色首页 `/admin/home/worker|functionalAdmin|systemAdmin|superAdmin`）主区的「功能入口卡片」**不是**按菜单自动生成的，而是由各包 `shortcuts.php` 声明候选池、再由用户「定制」决定的；左侧菜单不受影响。

```php
<?php
// 包根 shortcuts.php —— 只声明菜单 id
return [
    'default'  => ['demo.index', 'demo.record'],   // 安装后默认展示，每包 ≤3
    'optional' => ['demo.settings'],               // 备选，用户在「定制」中勾选，每包 ≤20
];
```

- **只写菜单 id**：卡片的标题 / 路由 / 图标 / 权限全部取自 `menus.php` 对应项，这里**不要**重复写 `title`、`icon`、`url` 等展示属性（两处维护必然漂移）。
- **候选菜单要求**：必须是可跳转的**叶子菜单**（`route` 非空且没有子菜单）；父级分组节点、`route` 为空的菜单不会成为卡片。
- **权限过滤**：卡片沿用菜单的 `perms`；用户对某菜单无可见权限时，该卡片既不出现在首页，也不出现在「定制」候选池。
- **上限**：`default` ≤ 3、`optional` ≤ 20（`ShortcutRegistry::MAX_DEFAULT / MAX_OPTIONAL`）；超限按声明顺序截断并记安装警告，**不阻断安装**。
- **同 id 冲突**：同一 id 同时出现在两组时按 `default` 处理（从 `optional` 中剔除）。
- **顺序**：候选池按「包登记顺序 → 组内声明顺序」排列；用户未定制时，首页展示各包 `default` 的并集。
- **无需写进 manifest**：`IntegrationManager` 按包根文件名读取，存在 `shortcuts.php` 即生效。平台脚手架 `PackageScaffold` 会自动生成一份（`default` 为 `['<short>.index']`），按实际功能调整。

#### 6.5.1 生效链路与用户侧行为

| 环节 | 说明 |
| --- | --- |
| 安装 / 升级 | `IntegrationManager` 读包根 `shortcuts.php` → `ShortcutRegistry` 按包覆盖写入 `data/integration/registry.json` 的 `shortcuts` 分区；删除包时随接入点一并清理 |
| 默认卡片注入 | 安装 / 升级成功后 `Package::appendDefaultShortcuts()` 把 `default` 追加到**已定制**用户的 `data/home/custom.json`；未定制用户无需落盘，渲染时直接取 `default` |
| 用户定制 | 首页右上「定制」抽屉：勾选 `optional`、拖拽排序、取消勾选即移除；保存走 `POST /admin/home/customSave`（`homeKey` + `menuIds`），只接受当前用户可见且已声明的 id（越权 id 一律剔除），`reset=1` 恢复默认 |
| 渲染 | `Home::homeShortcutOptions()` 用当前用户可见菜单拼候选池，`resolveSelected()` 按用户定制顺序产出首页卡片；卡片跳转地址由菜单 `route` 经 `url()` 生成 |

#### 6.5.2 配额建议

- `default` 只放日均最高频的 2~3 个业务入口（用户首屏最常点），不要用系统设置 / 低频管理项占位。
- `optional` 放其余能从左侧菜单进入的功能即可，不必把所有菜单都列一遍。
- 报表类卡片：先在 `menus.php` 侧按「报表中心合并」规则收敛（见 6.2），卡片仍指向合并后的菜单 id。

#### 6.5.3 验证

1. 安装后访问 `/admin/home`（或对应角色首页），确认 `default` 卡片已出现。
2. 点右上「定制」，确认 `optional` 卡片在备选池中，可勾选 / 拖拽排序 / 移除并保存成功。
3. 用无对应权限的账号访问，确认该卡片不显示，且不出现在「定制」候选池。

## 七、包路由（route.php）

功能包用**标准 ThinkPHP 路由结构**，由宿主 `PackageRouteLoader` 在 `AppService::boot()` 装配到共享 Route 实例。

**唯一写法（强制遵循）**：功能包路由**一律写裸路径**——不带 `/admin/` 前缀、不带前导 `/`，例如 `crm/customer/add`；同时 `code/host/.env` 的 `PACKAGE_ROUTE_FORCE_ADMIN` 必须保持 `0`。

```php
// code/plugins/<short>/route.php
declare(strict_types=1);
use think\facade\Route;

Route::get('crm/customer/index', 'Lg\Pack\Crm\controller\Customer@index');
Route::post('crm/customer/add',  'Lg\Pack\Crm\controller\Customer@add');
```

- 控制器用**全限定类名**（`Lg\Pack\...@method`），走框架 `CallbackDispatch`；类按包 composer.json PSR-4 放 `src/`。
- 只装配 `state=enabled` 的包；disabled 包源码在隔离区 + loader 跳过，双重失效。
- 菜单 `route` 也填**同一套裸路径**（如 `trade/product/index`），不带前导 `/`、不带 `admin/`：宿主渲染菜单时对非 `/` 开头的 route 调 `url()` 生成链接，得到 `/trade/product/index`，与实际请求一致。

### 7.1 为什么不能加 `admin/` 前缀

`PACKAGE_ROUTE_FORCE_ADMIN` 是宿主侧的历史遗留开关（`config/route.php` 的 `package_route_force_admin`，`PackageRouteLoader` 在开时用 `Route::group('admin', ...)` 包裹 `route.php`）。**当前架构下两种"加前缀"的做法都走不通，一律不要用**：

| 做法 | 规则实际注册成 | 结果 |
| --- | --- | --- |
| 包内自写 `admin/crm/customer/index`（`FORCE_ADMIN=0`） | `admin/crm/customer/index` | 404——包 URL 首段不是应用名（`admin`/`index`），多应用不剥前缀，保留完整路径去匹配，规则永远命中不到 |
| 包内写裸路径 + `FORCE_ADMIN=1` | `admin/crm/customer/index`（被 `Route::group('admin')` 补齐） | 同上，404；且会连带弄坏本已正常的包 |
| **包内写裸路径 + `FORCE_ADMIN=0`** | `crm/customer/index` | 正确命中 `/crm/customer/index` |

> **事故复盘（2026-10-25，lin-crm 404）**：宿主为 think-multi-app 架构，URL 首段为真实应用名（`admin`/`index`）时才剥前缀；包 URL 不是应用名，多应用会保留完整路径去匹配全局路由。而菜单 URL 由 `url($route)` 生成，结果恒为裸路径（`/crm/customer/index`）。因此只有裸路径规则能命中实际请求。
>
> 结论：**包内 `route.php` 与菜单 `route` 一律写裸路径，`.env` 的 `PACKAGE_ROUTE_FORCE_ADMIN` 保持 `0`**（参照 `code/plugins/lin-trade/route.php`）。宿主侧的"强制补齐"机制在修正前不要启用。

### 7.2 包页面（GUI）渲染规范（强制）

**每个 `menus.php` 声明 `route` 的叶子菜单，必须有对应的 GUI 页面**——菜单路由指向 JSON 方法会导致浏览器直接输出 JSON，等于页面缺失。宿主**未给包配置 view_path**，包页面不走路由到模板的框架解析，唯一正确模式（参照 `lin-trade` 的 `TradeController::render()` 与 `PackageScaffold::indexController()`）：

**① 视图文件**：放 `src/view/<模块>/<页面>.html`，**纯静态 HTML + 前端 JS**（Vue3 + ElementPlus + workdesktop-ai UMD 直引），无服务端模板变量。页面骨架四件套（参照 `lin-trade/src/view/product/index.html`）：

```html
<script type="text/x-template" id="xxx-tpl"><!-- wd-panel/wd-data-grid/wd-drawer-button 等 --></script>
<script src="/static/vendor/vue/vue.global.prod.js"></script>
<script src="/static/vendor/element-plus/index.full.min.js"></script>
<script src="/static/vendor/icons/index.iife.min.js"></script>
<script src="/static/vendor/workdesktop-ai/index.umd.js"></script>
<script> /* Vue.createApp({ template: '#xxx-tpl', ... }); app.use(ElementPlus); app.use(WorkDesktop); app.mount('#app'); */ </script>
```

**② 控制器渲染方法**：对齐宿主 admin 控制器范式（`index()` 里 `return $this->app->view->fetch(...)`）——用 **`think\facade\View` 渲染并直接 `return` 渲染结果字符串**，由框架自动包装为 Html 响应；**页面方法不声明返回类型**（门禁失败时需返回 redirect/Response，与字符串混合返回，声明类型会触发 `Return value must be of type ...` 运行时错误）。宿主未为包配置 view_path，运行时把引擎 `view_path` 指到包内 `src/view/` 即可（同 `lin-trade` 引擎分支）；包页面为纯 HTML+前端 JS、不含模板标签，引擎渲染实测无副作用：

```php
use think\facade\View;

/** 页面壳：门禁 → 渲染空壳，数据由前端组件拉 JSON 接口。 */
public function pageCustomer()
{
    $gate = $this->gatePage('crm:customer:view'); // 未登录 302 登录页；无权限 403；通过返回身份
    if (!$gate instanceof Identity) {
        return $gate;
    }
    return $this->render('customer/index');       // 字符串直接返回，框架包装响应
}

protected function render(string $template, array $data = []): string
{
    $viewPath = dirname(__DIR__, 2) . '/src/view/';
    if (!is_file($viewPath . $template . '.html')) {
        abort(404, '页面缺失：' . htmlspecialchars($template));
    }
    View::engine()->config(['view_path' => $viewPath]);
    return View::fetch('/' . $template, $data);
}
```

> 历史注记：lin-trade 的 `TradeController::render()` 主路径用 `file_get_contents` 读文件直返，起因是页面 JS 里的 `{load()}` 会被模板引擎误判——但这是宿主 admin 模板（含 `{$var}` 服务端变量）与包纯静态页混用时的历史坑；包页面不含任何 `{$var}`/`{:fn()}`/`{if}` 等模板语法时，走引擎与直读文件等价（lin-crm 已逐字节比对验证）。两种写法都合规，**范式优先**；若页面确需引入模板敏感语法，用 `{literal}...{/literal}` 包裹 JS 或退回读文件直返。

**③ 路由与命名分离**：

- 页面路由（菜单入口）：`GET <路径>` → 控制器 `pageXxx` 方法，**首行权限门禁**（`checkPerm`）后 `render()`；
- 数据路由：JSON 列表放 `POST <路径>/rows`，返回平台数据网格形状 **`{list, total, pageSize, currentPage}`**（ThinkPHP `paginate()` 需转换，不能直接吐原始分页对象）；
- 参数读取需兼容前端组件嵌套 `param` 与平铺两种写法（取 `param` 优先）；
- 同一列表页多视角（如公海/私海）复用同一视图文件，页面 JS 按路径/查询参数切初始过滤，`onMounted` 补一次带参查询。

**④ 上线前自检**：菜单 `route` ↔ `route.php` GET 路由 ↔ 控制器 `pageXxx` 方法 ↔ `src/view` 视图文件**四级对齐**（可用脚本静态扫描，参照 `temp/crm_gui_coverage_check.php`）。

## 八、生命周期与接入

状态机：`absent → enabled ⇄ disabled → absent`（升级/回退不改状态）。

| 阶段    | 引擎（`linhub/host/src/lifecycle/`）        | 关键点                                                |
| ----- | --------------------------------------- | -------------------------------------------------- |
| 打包    | `PackagePacker`                         | `pack()` 需 ext-zip；入包前先跑 manifest 校验               |
| 安装    | `PackageInstaller`                      | 完整性→依赖→平台兼容→备份→落地源码→迁移(S3)→接入(S4)→置 enabled；失败整体回滚 |
| 升级/回退 | `PackageUpgrader` / `PackageRollbacker` | 备份→替换/还原→迁移 up/down→接入；不改状态                        |
| 禁用/启用 | `ToggleManager`                         | enabled⇄disabled，源码移入/移出隔离区并注册/注销接入点               |
| 删除    | `PackageRemover`                        | 高风险，需 `confirmed=true`                             |

- **接入点（S4）**：`IntegrationManager` 从 `loadRoot/<short>/` 读五类声明文件登记到 registry JSON（权限/菜单/工作台/界面替换/首页快捷入口）。
- **迁移（S3）**：`MigrationManager` 提供 `installHandler/upgradeHandler/rollbackHandler`，脚本位于 `loadRoot/<short>/migrations/<版本>/`。
- **审核（需求 F）**：新装与升级都必须审核通过（审核记录在 `code/host/data/plugin-review.json`，路径由 `.env` 的 `PACKAGE_REVIEW_FILE` 决定；按包指纹校验）；未审过 install/upgrade 返 423。
- **守卫参与**：生命周期每步经 `PlatformAccessGuard::requirePlatformEntry()`（准入留痕 + 审计）。
- **生命周期广播**：宿主在安装/升级/卸载/打包**成功后**，向所有功能包广播生命周期事件（`MessagingService::broadcastLifecycle`，投递失败只记不抛，不影响主流程）：

| 触发节点（admin Package 控制器） | 广播主题                            | 载荷字段                                |
| ----------------------- | ------------------------------- | ----------------------------------- |
| install 成功              | `lg.platform.package.installed` | `short`、`version`                   |
| upgrade 成功              | `lg.platform.package.upgraded`  | `short`、`from_version`、`to_version` |
| remove 成功               | `lg.platform.package.removed`   | `short`、`name`                      |
| pack 成功（zip / 目录包）      | `lg.platform.package.packed`    | `short`                             |

功能包订阅这些主题即可感知平台上其他包的增删升（见下一节），例如订阅 `installed` 后清缓存、订阅 `removed` 后清理本包缓存的对方数据。

## 九、事件广播与订阅（messaging 服务）

功能包间的消息/事件走平台 **messaging 服务**（`services/messaging`，共享进程内事件总线 Broker，实现见 `MessagingService`）。两个方向都支持：

- **被动接收**：订阅宿主生命周期广播或其他功能包的业务事件；
- **主动发布**：广播本包业务事件，供其他功能包订阅（跨包联动主通道，如 `lg.crm.deal.closed` → 林销自动转销售草稿）。

### 9.1 主题命名（M008）

| 主题形态                | 用途                | 示例                              |
| ------------------- | ----------------- | ------------------------------- |
| `lg.<short>.*`      | 功能包自有主题（发布方 = 本包） | `lg.trade.product.created`      |
| `lg.<otherShort>.*` | 订阅他包主题（跨包联动）      | `lg.crm.deal.closed`            |
| `lg.platform.*`     | 宿主保留前缀（生命周期广播）    | `lg.platform.package.installed` |

校验规则（M008）：`subscribes.topic` 必须是 `lg.<word>.` 分段主题（`<word>` 为小写字母/数字/`-`），本方、跨包、宿主前缀均放行；坏形状（如 `member.updated`）安装时被拦。

### 9.2 manifest 声明订阅（权威装配路径）

```php
// manifest.php
'subscribes'  => [
    ['topic' => 'lg.platform.package.installed', 'handler' => 'Lg\\Pack\\Demo\\Subscribers\\DemoHandler'],
    ['topic' => 'lg.crm.deal.closed',              'handler' => 'Lg\\Pack\\Demo\\Subscribers\\DemoHandler'],
],
```

- 宿主 `PackageRouteLoader` 每次请求汇总**已启用**包的 `subscribes`，注册进共享事件总线（幂等）。
- 一个 handler 类可对应多个主题（在 `handle` 内按 `$event->topic` 分发，参考 `lin-trade` 的 `Subscribers`）。

### 9.3 handler 契约

```php
use linhub\host\communication\broker\Event;

class DemoHandler
{
    public function handle(Event $event): void
    {
        $payload = $event->payload;   // array 载荷
        $topic   = $event->topic;     // 按主题分发
        $source  = $event->source;   // 发布方
        // 业务处理；异常请自行 try/catch——宿主侧重试后吞掉，但不应依赖宿主兜底
    }
}
```

- **无参构造 +** **`handle(Event $event)`** 是唯一支持的形态（`HandlerCaller` 反射调用）；不支持 `Class@method` 写法。
- 投递语义：发布方 `publish` **绝不因消费者失败抛错**（宿主按 maxRetry 重试后吞掉）；handler 应自行兜底异常并记日志。

### 9.4 发布事件（requires 声明 + 运行时获取）

```php
// manifest.php：'services' => ['requires' => ['config', 'logging', 'id', 'messaging'], ...]

use linhub\host\communication\HostServiceApi;

$messaging = HostServiceApi::inject($this->app, ['messaging'], 'demo')['messaging'];
$messaging->publish('lg.demo.order.created', ['order_id' => 42]);
```

- 先落库后广播：业务事件应在**事务提交后**发布，保证消费者看到的数据已持久化（参考 lin-trade 的 `TradeEvents`）。
- 发布失败降级：建议 try/catch 后记日志，不让事件总线故障影响主流程。

## 十一、功能包落位与安装（首次生成后必读）

> **重要（强制遵循）**：新功能包**首次生成（尚未安装）时，必须放在功能包临时存放区（暂存区），不得直接写进安装落地根 `code/plugins/`**；落位完成后**再调用 CLI 执行安装**（走与用户手动点击安装完全相同的链路）。若安装无法完整走通，**不要绕过链路手搬文件**，而是明确提示用户手动安装。

### 11.1 落位：先放暂存区

暂存区根由 `code/host/.env` 的 `PACKAGE_STAGING_ROOT` 决定（相对路径基于 `code/host` 解析；当前配置为 `package/staging`，即 `code/host/package/staging/`）：

```
code/host/package/staging/
└─ lgg-pkg-<short>/        # 目录名必须带 lgg-pkg- 前缀，与 manifest.short 对应
   ├─ manifest.php
   ├─ composer.json
   ├─ route.php
   ├─ permissions.php
   ├─ menus.php
   ├─ workspace.php        # 可选（工作台插槽）
   ├─ ui_replace.php       # 可选（界面替换）
   ├─ shortcuts.php        # 可选（首页快捷入口）
   ├─ migrations/
   └─ src/                 # Controller / Service / Support / view / Subscribers
```

- 目录名**必须**为 `lgg-pkg-<short>`：安装接口按 `target=lgg-pkg-<short>` 定位，非该前缀直接返回 422。
- 目标目录必须位于暂存根内（安装接口用 `realpath` 比对，防路径逃逸）。
- **不要**把新包直接放到 `PACKAGE_LOAD_ROOT`（当前 `../plugins` → `code/plugins/`）：那是安装器的落地根，手工投放会造成 `plugin-state.json` 无记录、路由与接入点不生效。`code/plugins/` 下的既有包是**已安装**的产物，不是生成入口。
- 平台自身的「新建功能包」动作（`PackageScaffold`）同样是生成到暂存区，可作参照。

### 11.2 安装：调用 CLI（模拟用户手动操作）

安装走的是管理页同一套接口与链路（审核 → 安装 → 迁移 → 接入 → 置 enabled），**不手搬文件、不改** **`plugin-state.json`、不改** **`registry.json`**。

前置：服务已启动（如 `php think run`），且具备可用的超管会话。

```powershell
$base = 'http://127.0.0.1:8213'                       # 按实际监听端口替换（06 指引统一用 8213）
$pkg  = 'lgg-pkg-<short>'                             # 暂存区目录名

# ① 登录，保存会话 Cookie（模拟用户登录）
curl.exe -c cookies.txt -X POST "$base/admin/auth/doLogin" `
  -d "username=<超管账号>&password=<超管密码>"

# ② 接入审核必须先行（需求 F：未审核通过 install 返 423）
curl.exe -b cookies.txt -X POST "$base/admin/package_review/approve" `
  -d "target=$pkg"

# ③ 安装（与用户在管理页点「安装」完全一致）
curl.exe -b cookies.txt -X POST "$base/admin/package/install" `
  -d "target=$pkg"
```

- 判定结果看 JSON 的 `code` 字段（`code>=0` 成功），**不要**判 `success`（铁律 5）。
- 安装成功后可再验证：包路由 200、菜单/权限已登记、`plugin-state.json` 中该包 `state=enabled`。
- 升级同理：新版本放同名暂存目录 → 审核 → `POST /admin/package/upgrade`。

### 11.3 安装不完整时：提示用户手动安装

出现以下任一情况，视为“无法完整安装”，**保留暂存目录原样、不要改动平台数据文件**，并向用户明确说明原因与手动步骤：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 请求 302 跳登录页 / 返回 `-401` | 无可用超管会话或凭证缺失 | 提示用户登录管理页手动安装 |
| `code` 非 0 且 HTTP 423 | 该版本未审核通过，或包内容变化导致指纹失效（`changed`） | 提示用户先在「功能包审核」页通过审核，再安装 |
| `安装前无法连接数据库，不能执行建表迁移` | 数据库不可达 | 提示用户检查 `.env` 的 `DB_*` 后手动安装 |
| 完整性/依赖/平台版本报错（M00x） | manifest 不合规、依赖缺失、平台版本不满足 | 修复包后重新落位，或交用户确认 |
| 环境缺扩展（如 ext-zip） | 打包/解压能力不足 | 提示用户处理环境后手动安装 |

给用户的手动安装路径：登录管理页 →「功能包管理」→ 暂存包列表确认包已识别 →「功能包审核」通过 →「安装」。**不得**用复制目录、手改状态文件等方式伪造安装结果。

## 十三、常见坑

1. **装不上报 M011**：`access=public + sign=none` 且路径不在宿主"安全探活清单"——默认安装的包保持 `admin`。
2. **迁移脚本找不到**：安装器与 `MigrationManager` 必须共用同一 `loadRoot`，脚本放 `{loadRoot}/{short}/migrations/{version}/`。
3. **Model 表不存在**：用 `protected $table='lg_demo_record'` 完整表名，不写 `$name`+`$prefix`。
4. **包路由失效**：确认 `data/plugin-state.json` 中 `state=enabled`；控制器类用全限定类名且 PSR-4 路径一致。
5. **找不到** **`linhub\host\Version`**：宿主同进程自动加载，不要在包内 require；独立脚本需自行引宿主的 `vendor/autoload.php`。
6. **升级源码落空目录**：经 Junction 加载时 `dirname(__DIR__,N)` 需先 `realpath(__DIR__)` 再回溯（memory \[eval] #18）。
7. **订阅写** **`Class@method`** **不生效**：宿主 handler 契约只支持无参构造 + `handle(Event $event)`；多主题一个类，在 handle 内按 `$event->topic` 分发（见第九节）。
8. **新包直接放进** **`code/plugins/`**：那是安装落地根，手工投放无 `plugin-state.json` 记录、路由与菜单都不生效——必须先落暂存区（`PACKAGE_STAGING_ROOT`）再走安装（见第十一节）。
9. **首页快捷入口卡片不显示**：`shortcuts.php` 引用的必须是 `menus.php` 里**可跳转的叶子菜单 id**；父级菜单、`route` 为空的菜单、当前用户无权限的菜单都会被静默过滤（不报错），排查时先核对菜单 id 与权限（见 6.5）。
10. **菜单点开输出 JSON / 页面空白**：叶子菜单 `route` 指向了 JSON 方法，或误用 `$this->app->view->fetch()`（宿主未给包配 view_path，包页面必须走 7.2 的读文件渲染模式）。自检：菜单 route ↔ GET 路由 ↔ `pageXxx` 方法 ↔ `src/view` 视图四级对齐。
