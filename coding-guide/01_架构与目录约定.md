## 三、总体架构分层

```
┌─────────────────────────────────────────────────────────┐
│ 功能包（插件）层   code/plugins/<short>/                  │
│   独立交付单元：manifest + 五类声明 + route.php + src/    │
│   命名空间 Lg\Pack\X / 表前缀 lg_<short>_ / 事件 lg.<short>. │
└──────────────┬──────────────────────────────────────────┘
               │ 安装/升级/启停（lifecycle）+ 接入点注册（integration）
┌──────────────▼──────────────────────────────────────────┐
│ 平台库层   code/host/linhub/                              │
│   linhub/capability   基础能力（auth 身份，无容器耦合）    │
│   linhub/host         宿主内核（服务/迁移/生命周期/RBAC/安全）│
│   linhub/admin        中后台应用（app\admin，独立 Composer 包）│
└──────────────┬──────────────────────────────────────────┘
               │ app_map 映射 + AppService 装配
┌──────────────▼──────────────────────────────────────────┐
│ 应用层   code/host/app/                                   │
│   仅开发者自己的代码：index 应用 / 中间件 / 装配 / 配置     │
└─────────────────────────────────────────────────────────┘
```

**依赖方向（单向，不得反向）**：`app/` → `linhub/*`；`linhub/host` → `linhub/capability`；功能包只依赖宿主公开接口（`linhub/host`），平台内核不依赖任何功能包。

## 五、Composer 库边界

根工程 `code/host/composer.json` 以 **path repository + require** 引入三个平台库：

```json
"require": {
    "linhub/capability": "*",
    "linhub/host": "*",
    "linhub/admin": "*"
},
"repositories": [
    { "type": "path", "url": "linhub/capability" },
    { "type": "path", "url": "linhub/host" },
    { "type": "path", "url": "linhub/admin" }
]
```

- 各库自带 `composer.json` 声明 PSR-4 映射：`linhub\host\` → `src/`、`linhub\capability\` → `src/`、`app\admin\` → `src/`。
- 根工程 autoload 只保留 `"app\\": "app"` 与功能包示例映射；**不要**在根工程重复注册 `linhub\*` 映射（避免冲突）。
- 改动平台库目录后必须 `composer dump-autoload`，否则类找不到 500。

## 六、多应用机制与路由

- 默认应用 `index`（公开），中后台 `admin` 通过 `config/app.php` 的 `app_map` 把应用目录指到 `linhub/admin/src`：

```php
'app_map' => [
    'admin' => function ($app) {
        $app->http->path(dirname(__DIR__) . DIRECTORY_SEPARATOR . 'linhub' . DIRECTORY_SEPARATOR . 'admin' . DIRECTORY_SEPARATOR . 'src');
        return 'admin';
    },
],
```

- 中后台 URL 一律带 `/admin/` 前缀，如 `/admin/role/index`；公开应用 `/index/...`；功能包路由**一律裸路径**（如 `trade/product/index`，不带 `admin/` 前缀与前导 `/`，且 `PACKAGE_ROUTE_FORCE_ADMIN=0`），由 `PackageRouteLoader` 装配到共享 Route。
- 路由**显式登记**在 `linhub/admin/src/route/app.php`：页面用 PascalCase 显式路由（如 `services/dashboard` → `service_governance/dashboard`），数据接口 snake\_case；`home` 相关路由需 `->completeMatch()` 防止前缀误匹配。
- 中后台登录守卫：`app/admin/middleware.php` 注册 `RequireLogin`，白名单仅 `auth/login`、`auth/doLogin`；**免登录内容约定自建独立应用，不放 admin**。
- 根路径 `/` 落到 index 应用，重定向 `/admin/home/dashboard`。

## 七、装配与启动链路

```
php think run（或 Web 入口 index.php）
  └─ AppService::boot() → (new \linhub\host\integration\PackageRouteLoader($this->app))->boot()
       ├─ 读 data/plugin-state.json，仅对 state=enabled 的功能包
       │    ├─ 注册 PSR-4 自动加载闭包（包 composer.json psr-4）
       │    └─ include 包 route.php → 路由注册到共享 Route
  └─ 多应用中间件 MultiApp → 应用（index/admin）路由
       └─ admin 应用 → RequireLogin 中间件（登录白名单）→ 控制器
            └─ AdminController::initialize() → new HostBootstrap($app)->ensureSeeded()
```

**HostBootstrap 是管理页的统一入口**：提供 `ensureSeeded()`（权限点/菜单/插槽幂等 seed）、`currentUser()`、`authService()`、`roles()`、`rbacUsers()`、`auditTrail()`、`menuTreeFor()` 等，管理控制器构造后即可用 `$this->bootstrap` 访问。

## 八、目录红线（不能碰什么）

1. `code/dist/`：只读，部署程序生成，禁止手动修改。
2. `code/host/linhub/`（平台库 capability/host/admin）与 `code/host/vendor/`：平台库与依赖，禁改；`code/host/app/` 是开发者代码区，`code/host/config/`、`code/host/.env` 按需修改（密钥不落码）。
3. `runtime/`：框架运行时缓存/日志，可重建；**插件源码落地在 `code/plugins/`、包状态/审核等业务数据在 `code/host/data/`**（不在 runtime），改前先备份。
4. `temp/`：临时产物，验证脚本可自由读写，但脚本开头须"幂等重置"自身染指的数据。
5. 平台库命名空间：一律 `linhub\host\*` / `linhub\capability\*`（全小写）；`app\host\*` 是历史命名，已不存在。
6. 外部文档（document/）：改文档按文档头规范，带版本号存档，历史版本改名 `_v[版本]` 保留。
7. `.env`：密钥配置，禁止提交；`.gitignore` 已排除。
